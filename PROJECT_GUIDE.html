Project overview

“This project helps faculty collect, review and organize examination questions, then compose papers from approved material using syllabus, marks and cognitive-level requirements. It supports manual authoring, document ingestion, AI-assisted generation and camera-based digitization.”

The problem

Questions are often spread across notebooks, books, old papers and digital files. Preparing a paper also requires checking marks, syllabus coverage, question repetition and the intended cognitive level.

The objective

Bring these tasks into one academic workflow: a reusable repository, suggested Bloom and CO tags, recorded faculty review, and a paper composer that selects approved material.

Who uses it?

Faculty author and review questions for assigned courses. Administrators and examination coordinators manage access, approve material, and oversee the examination workflow.

Opening explanation“Faculty ke questions alag-alag jagah hote hain—notes, books aur purane papers mein. Humne unhe ek repository mein organize kiya hai, jahan review aur approval ke baad paper banaya ja sakta hai.”

From source material to an examination

Author or ingest→Draft→Reviewed→Approved→Compose paper
  1. Choose a course and its syllabus context.
  2. Enter a question, upload a document, generate a draft, or scan a physical copy.
  3. Check the wording, formulas, options, marks, Bloom level and CO suggestion.
  4. Save a Draft. Exact duplicate questions in the same course are rejected.
  5. A faculty reviewer adds a comment and marks the question Reviewed.
  6. An administrator verifies the material and marks it Approved.
  7. The composer selects approved questions; faculty inspect the saved paper and export it.
Approval is meaningful: changing question content or its syllabus mapping returns it to Draft. Previous decisions and saved content versions remain in review history. Existing questions were not automatically approved during migration.
Main point“AI se aaya hua question seedha final paper mein nahi jata. Pehle Draft, phir faculty review aur admin approval hota hai. Edit karne par dobara review required hota hai.”

Capture and review

Use the rear camera when supported, or upload a JPEG, PNG, WebP or HEIC file smaller than 10 MB. Review, rotate or retake the photo. The browser prepares a smaller upload, and the server verifies the image’s actual format and dimensions.

Mathematical notation

Expressions are represented as LaTeX inside single dollar signs, for example $x^2 - 4 = 0$ or $\frac{1}{2}$. The app renders these using KaTeX, while instructors can still edit the source text.

What makes the review useful?

  • Compare the source photo beside the extracted content.
  • Edit the stem and MCQ options, with live mathematical previews.
  • Confirm a missing MCQ answer key before academic review.
  • Receive actionable errors for unreadable images, provider failure or missing configuration.

Live scanning requires a Gemini key and internet. Camera capture needs a supported browser and HTTPS or localhost. The manual drawer fills the first extracted question; use the synthesizer to review a multi-question image. Original image files are not persisted as repository attachments.

Bloom’s Taxonomy and Course Outcomes

Bloom’s Taxonomy describes the cognitive demand of a question. The classifier uses action verbs and linguistic cues to make an explainable suggestion; it is not a guarantee of the complete educational difficulty.

LevelMeaningIllustrative action
L1 · RememberRecall knowledge.Define a stack.
L2 · UnderstandExplain a concept.Explain recursion.
L3 · ApplyUse a method.Calculate an expression using a stack.
L4 · AnalyzeExamine relationships.Compare two search strategies.
L5 · EvaluateJudge using criteria.Justify an algorithm choice for a workload.
L6 · CreateDesign a solution.Design a scheduling strategy.

A Course Outcome states what a learner should achieve in that course. The mapper compares question content with syllabus units and CO descriptions, including Bloom-level cues, to suggest a mapping.

Explain the distinction: Bloom level answers “what cognitive task is required?” CO mapping answers “which course learning outcome does it assess?” Faculty must verify both suggestions in context.
Useful viva distinction“Bloom level question ke thinking level ko batata hai. CO mapping batati hai ki question course ke kaunse learning outcome ko assess karta hai. Dono same cheez nahi hain.”

How paper composition works

The composer receives a blueprint and an approved question pool. It uses constraint-based selection to construct the examination structure from eligible repository questions.

  • Marks and structure: examination totals, section requirements and selected question types.
  • Syllabus context: included units and Course Outcome information.
  • Academic balance: target Bloom and difficulty distributions.
  • Question reuse: repository IDs and usage data support selection and repetition checks.
  • Internal choices: alternatives represent an either/or question; their answerable marks are counted once.

Paper quality checks compare declared marks, section subtotals, internal-choice groups, duplicate IDs and the current approval/version of source questions. Replacements must be approved, belong to the paper’s course, and satisfy replacement constraints.

If the pool is insufficient: review the error and add or approve suitable questions. Target distributions should be inspected in the generated analytics; do not claim that every target is always met exactly for every available pool.
Composer explanation“Composer ke paas blueprint aur approved question pool hota hai. Woh marks, units aur question structure ke hisaab se selection karta hai. Faculty final coverage aur generated distribution inspect karti hai.”

Access is enforced by the backend, including uploads, batch operations, AI endpoints, paper replacements and PDF downloads. Public registration creates an unassigned faculty account; submitting an administrator role does not grant administrator access.

Sign-in is explicit. UI-entered Gemini keys use session storage and are cleared on account switches. Key validation does not overwrite shared backend credentials.

Local demo versus production: this local installation explicitly enables demo mode for demonstration accounts. Source defaults disable it. Production requires a private signing secret and rejects demo mode. Do not present demo credentials as a production authentication setup.

SQLite provides local relational storage. Schema migrations preserve existing content. Content edits invalidate approval, while history retains the previous tracked versions.

Backup and recovery

The backup tool uses SQLite’s online backup API and verifies database integrity. Restore is an explicit offline operation: stop all database writers first. The tool preserves the previous database before an atomic replacement.

Operational commands and recovery precautions are documented in docs/operations.md. Backups contain examination and account data; store them privately. Never perform a live restore as part of the demonstration.

Viva questions and concise answers

What is the main contribution of this project?

It connects question ingestion, academic tagging, human review and approved-pool paper composition in one faculty workflow.

Where is AI used?

Gemini handles requested image understanding and LLM generation. Bloom classification and CO suggestions also use local explainable rule/keyword logic. These are different mechanisms and should be described separately.

How does scanning differ from generating a new question?

Extraction digitizes the question visible in the photo. Synthesis uses the photo’s concept to request a new question under chosen academic controls.

How are mathematical formulas handled?

The transcription uses LaTeX inside dollar signs. KaTeX renders it in the interface. The instructor compares the rendered formula with the source image before saving and reviewing it.

How do you prevent unsuitable AI output reaching a paper?

AI output remains editable draft material. Review and administrator approval are required before the composer can select it. Validation catches structural issues, but mathematical and academic correctness still need faculty checking.

Does Bloom classification fully measure difficulty?

No. The current classifier suggests cognitive levels using action verbs and linguistic cues. The full task, subject context and expected answer matter; faculty verify the suggestion.

Why use SQLite?

It fits the current local application and supports relational models and straightforward backup. A larger multi-user deployment would need a separate concurrency, operations and database-scaling assessment.

How are duplicates handled?

Normalized exact duplicate stems are checked within a course when saving. The editor also shows advisory similar-question matches over the latest 1,000 course entries. Similarity is not a proof of semantic equivalence.

What happens if the API key is missing or the photo is unclear?

The scan returns an actionable error. It does not replace an unreadable photo with invented questions. Topic/document generation can return clearly identified template drafts when its fallback is used.

What should be improved next?

A broader real-image evaluation set, more end-to-end automation, subject-specific semantic validation, and verified marking rubrics would improve the system. These are future improvements, not claims about the current implementation.

Validation and honest boundaries

The latest verified implementation run passed 94 backend tests. The frontend production build and lint command also passed, with existing warnings. These results describe that run and are not a guarantee of academic correctness or future changes.

  • Tests cover classification, paper composition, image validation, vision error paths, access control, review transitions, duplicates, pagination, history and database backup.
  • Desktop and mobile browser checks covered the repository, review panel and duplicate feedback.
  • PDF/DOCX ingestion and text synthesis have regression checks.
  • Live Gemini transcription and physical-camera hardware accuracy still need a representative real-device evaluation.

What not to claim during explanation

  • Do not claim zero OCR errors or guaranteed mathematical correctness.
  • Do not describe action-verb classification as a fully semantic assessment model.
  • Do not claim that demo mode is suitable for production.
  • Do not say all blueprint distribution targets are exact without inspecting that generated paper.
  • Do not claim automatic verified solutions or marking rubrics; those are not implemented as a guaranteed feature.
